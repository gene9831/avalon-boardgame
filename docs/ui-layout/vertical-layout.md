# 竖向房间布局

## 范围与所有权

本文记录当前生产 Web 的竖向布局契约。`RoomScreen` 通过 `RoomLayout` 提供语义槽位；`@avalon/ui-layout/room-layout.css` 的容器查询决定形状。JavaScript 只测量最终舞台内容盒并交给纯圆桌求解器，不能选择布局模式。圆桌、座位与桌心的几何由[圆桌舞台布局规范](./round-table-stage-layout.md)定义。

## 结构

竖向容器使用 56px 顶部 chrome，随后是可伸缩舞台与底部阶段区域：

```text
有效内容矩形（扣除安全区）
├── 顶部 chrome：56px
│   ├── 返回、房间号、五次任务进度
├── 舞台区域（8px；容器高至少 800px 时为 12px 内边距）
│   └── 实测 stage content box → round-table solver
└── 阶段区域
    ├── heading：阶段名称和工具栏
    ├── middle：说明、选择或私有反馈
    └── action：底部唯一状态变更操作（3.5rem 槽）
```

底部阶段区域的总预算是 160px 加上安全区补偿；没有阶段按钮时仍保留 action 槽，避免舞台因阶段变化跳动。所有公开操作热区至少 44px。安全区只由 `room-layout.css` 扣除一次。

## 实测边界与验收

竖向代表尺寸为 375×667 与 390×844。2026-09-11 的 10 人满员大厅实测 375×667 stage content box 为 **359×427**，求解为 stadium；所有座位和可见产品控件均在视口内。

五个等待大厅演示页（玩家/房主 × 未满员/满员，以及当前玩家掉线）均可在 5–10 人间切换。阶段槽位行为为：

- 房主未满员：禁用“开始游戏”；满员后可开始，待决时显示“正在开始…”。
- 普通玩家：只显示等待文案，不出现底部开始按钮。
- 重连：先自动恢复；八秒后才在 action 槽给出“重新连接”。帮助和公开记录可用，改变房间的操作不可用。

身份辨认仍使用既有的舞台幕布，本布局切片没有重设计它。
