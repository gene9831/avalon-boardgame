# 竖向房间业务外壳布局

## 1. 文档范围

本文只定义 Avalon 房间在竖向空间中的业务外壳：顶栏、圆桌舞台容器和底部阶段操作栏。圆桌桌面、桌心和玩家座位的几何由[圆桌舞台布局规范](./round-table-stage-layout.md)统一定义，不属于本文职责。

当前实现位于独立的 [`apps/ui-layout-lab`](../../apps/ui-layout-lab/README.md)；旧[统一横竖屏交互原型](./prototypes/avalon-landscape-responsive-lab.html)暂时保留为横向策略迁移的对齐参考。

## 2. 职责边界

业务外壳负责：

- 读取视口和设备安全区；
- 布局顶栏与底部阶段操作栏；
- 决定舞台外边距；
- 测量最终舞台内容盒；
- 将测得的 `maxStageWidth`、`maxStageHeight`、`playerCount` 与可选的玩家座位边界最小间距、最大头像尺寸、头像递减步长传给圆桌舞台求解器。

圆桌舞台求解器不读取视口、不计算顶栏或底栏，也不扣除安全区。业务侧传入的舞台尺寸是硬边界，不能再由求解器二次缩小。

## 3. 顶层结构

```text
有效页面矩形
├── 顶栏
├── 舞台区域
│   └── 外边距
│       └── 圆桌舞台内容盒
└── 底部阶段栏
    ├── 阶段标题：48
    ├── 阶段内容：56
    ├── 阶段操作：56
    └── 底部留白：max(8, safe-area-inset-bottom)
```

三个顶层区域直接相邻。分隔线可以覆盖边界，但不额外占用高度。底部阶段栏不是抽屉，游戏内容不能改变它的三个内容矩形高度。

## 4. 业务外壳参数

竖向预览按页面高度选用两档顶部外壳；底部内容不再设紧凑档。

| 参数 | 页面高度小于 800 | 页面高度至少 800 |
| --- | ---: | ---: |
| `topBarHeight` | 48 | 56 |
| `topBarPadding` | 8 | 12 |
| `stageMargin` | 8 | 12 |
| `phaseHeaderHeight` | 48 | 48 |
| `phaseMiddleHeight` | 56 | 56 |
| `phaseActionHeight` | 56 | 56 |

因此：

```text
phaseContentHeight = 48 + 56 + 56 = 160
phaseBottomClearance = max(8, safe-area-inset-bottom)
phasePanelHeight = phaseContentHeight + phaseBottomClearance
```

底部留白使用阶段栏自身背景。模拟尺寸模式不伪造设备安全区；没有真实安全区时取 8。

## 5. 舞台尺寸分配

设业务侧已经取得可用页面尺寸 `usableWidth` 和 `usableHeight`：

```text
stageRegionHeight = usableHeight
    - topBarHeight
    - phasePanelHeight

maxStageWidth = usableWidth
    - 2 × stageMargin

maxStageHeight = stageRegionHeight
    - 2 × stageMargin
```

外壳应测量圆桌舞台内容盒的实际 `clientWidth` 与 `clientHeight`，而不是在调用点重复推导 CSS。字体加载、浏览器安全区或容器变化导致内容盒尺寸变化时，应重新求解。

当前实验页只接入高舞台策略。若设备模式分配出的舞台区域大于该策略的同步求解边界，业务外壳在区域内水平、垂直居中一个最大 `744×800` 的求解内容盒，再测量该盒并传给求解器；多余空间仍属于舞台背景，不由求解器填满。该裁切是实验页的调用策略，不改变纯函数只处理传入硬边界的职责。

页面的最小支持尺寸属于业务产品约束，不是圆桌舞台求解器的输入校验。当前竖向验收仍以 375×667 作为最小代表尺寸。

## 6. 顶栏

顶栏从左到右包含返回入口、房间信息和五个任务进度。当前预览用固定 44 的任务槽位展示五个节点，任务轨道总宽度为 220。返回入口和所有工具热区至少为 44×44。

房间信息使用剩余宽度；空间不足时可以在自身区域内换行，但不能挤压任务轨道或截断房间号。身份、记录和帮助入口位于底部阶段栏标题行，不进入圆桌舞台。

## 7. 底部阶段栏

阶段栏内容固定为三个不收缩、不滚动的矩形：

```text
PhaseContent
├── Header：48；阶段标题与身份、记录、帮助
├── Middle：56；横向选择或简短说明
└── Action：56；单个主要操作
```

Action 内的主要按钮高度为 44，因此上下各留 6。主要按钮文本保持单行；空间不足时应缩短业务文案或省略次要内容，不增加按钮或 Action 高度。

等待状态可以不显示按钮，但仍保留对应矩形。游戏阶段变化不得导致阶段栏高度或圆桌舞台位置跳动。

## 8. 代表尺寸

以下示例假设页面没有额外顶部安全区，底部安全区小于 8：

| 页面尺寸 | 顶栏 | 底栏内容 | 底部留白 | 舞台外边距 | 传给求解器的舞台尺寸 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 375×667 | 48 | 160 | 8 | 8 | 359×435 |
| 390×844 | 56 | 160 | 8 | 12 | 366×596 |
| 430×932 | 56 | 160 | 8 | 12 | 406×684 |
| 768×1024 | 56 | 160 | 8 | 12 | 744×776 |

这些舞台尺寸是不包含顶栏、底栏或外边距的完整舞台输入。实验室默认使用 8px 的玩家座位边界最小间距，并允许独立调整；该参数不改变业务外壳几何。

## 9. 验收规则

1. 顶栏和底栏由业务外壳渲染，不出现在圆桌舞台求解结果中。
2. 底栏三个内容矩形始终为 `48 + 56 + 56 = 160`。
3. 底栏最下方额外保留 `max(8, safe-area-inset-bottom)`。
4. 44 高主按钮在 56 高 Action 内上下各留 6，文本保持单行。
5. 舞台传入尺寸等于最终内容盒的实际宽高，安全区和外边距只扣除一次。
6. 圆桌布局不可用时，错误只显示在舞台内；顶栏、底栏和设置入口仍可使用。
7. 设置面板、诊断显示与游戏状态变化都不得改变业务外壳的基础几何。

## 10. 与正式 Web 的关系

本文和独立实验室是目标布局规范，正式 Web 尚未迁移到该房间外壳。迁移时业务组件可以采用不同的 CSS 结构，但必须保持相同职责边界，并只把舞台硬边界、玩家人数和可选的座位求解参数交给纯几何 API。
