# 角色视野矩阵（MVP）

## 基础角色

| 观察者 | 可见信息 |
|---|---|
| 普通好人 | 只知道自己的阵营和身份 |
| 梅林 | 所有坏人玩家的座位 |
| 刺客 | 其他坏人玩家的座位；不能直接知道梅林是谁 |
| 普通坏人 | 其他坏人玩家的座位 |

MVP 不启用 Mordred 和 Oberon，因此梅林能看到全部坏人座位，坏人也能互相认识。梅林和坏人都只能获得阵营座位信息，不能由此知道某个坏人的精确角色是刺客还是爪牙。

## 开局身份辨认

开局在首次组队前依次进行三个辨认步骤：

1. **查看身份**：所有玩家只查看自己的完整角色信息；尚不释放任何其他座位的阵营视野。
2. **邪恶阵营辨认**：只有邪恶阵营玩家查看其他邪恶座位，不显示对方的刺客/爪牙精确角色。
3. **梅林辨认**：只有梅林查看全部邪恶座位，不显示各邪恶座位的精确角色。

每个步骤只公开匿名确认进度，不公开已确认玩家的座位。步骤全部完成后，正常游戏阶段继续保留上述授权视野。

## 扩展角色加入后的变化

| 角色 | 视野变化 |
|---|---|
| Mordred | 坏人身份，但不出现在梅林视野中 |
| Oberon | 不出现在其他坏人视野中，也看不到其他坏人 |
| Morgana | 在 Percival 视野中伪装成梅林 |
| Percival | 能看到梅林；如果有 Morgana，则同时看到梅林和 Morgana |

## 实现约束

- 角色身份和完整视野只能由服务端保存。
- 每个客户端只能收到自己的过滤视图。
- 开局辨认信息只能在对应步骤向参与者释放；幕布等前端隐藏不是安全边界。
- 匿名确认进度不能包含已确认玩家的座位或身份。
- 公开的 boardgame.io `ctx`、active-player move 计数或其他框架元数据不能编码辨认确认者或截止线唤醒者的座位。
- 实时与持久化游戏日志都不能保留辨认确认者或截止线唤醒者的座位。
- 不能只在前端隐藏角色名称。
- 任务秘密选择结果在全部提交前不能公开。
- 任务结果揭示时只能公开成功/失败数量或规则要求的结果，不公开单张牌对应的玩家。
